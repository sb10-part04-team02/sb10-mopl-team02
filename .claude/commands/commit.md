# 📄 Git Commit 커맨드

## 사용법

```
/commit
```

- 인자 없이 실행하면 현재 변경사항을 분석해 커밋 메시지를 제안한다.

## 동작 순서

1. `git status`와 `git diff` (staged + unstaged)를 실행해 변경사항 전체를 파악한다.
2. 변경된 파일과 내용을 분석해 커밋 타입과 한글 메시지를 결정한다.
3. 스테이징되지 않은 파일이 있으면 어떤 파일을 포함할지 사용자에게 먼저 확인한다.
4. **사용자 승인을 받기 전에** 커밋 메시지 초안을 `.local/claude/commits/`에 md로 저장한다. (아래 `## 초안 저장` 참고)
5. 아래 형식으로 커밋 메시지를 제안하고 승인을 받은 뒤 커밋한다.

## 커밋 메시지 형식

```
<type>: <한글 메시지>
```

### 타입 선택 기준

| 타입 | 사용 시점 |
|------|----------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 개선 |
| `docs` | 문서, 주석 변경 |
| `test` | 테스트 코드 추가/수정 |
| `chore` | 빌드, 설정, 의존성 등 기타 변경 |

### 한글 메시지 작성 규칙

- 무엇을 했는지가 아니라 **왜 했는지, 어떤 문제를 해결했는지** 중심으로 작성
- 명사형 종결 (예: `~추가`, `~수정`, `~제거`, `~개선`)
- 50자 이내로 간결하게

### 예시

```
feat: 좋아요 기능 추가
fix: 토큰 만료 시 재발급 로직 누락 수정
refactor: TrackingService 버퍼 flush 조건 분리
chore: Flyway 마이그레이션 스크립트 추가
```

## 초안 저장

**사용자 승인을 받기 전에** 커밋 메시지 초안을 로컬에 저장한다. (커밋 해시는 아직 없으므로 메시지 slug 사용)

- 경로: `.local/claude/commits/<YYYYMMDD>-commit-<slug>.md`
- `slug`: 커밋 메시지를 소문자 영문/숫자/하이픈으로 정리한 값 (예: `feat: 좋아요 기능 추가` -> `like-feature`)
- 내용: 커밋 메시지 / 포함할 파일 목록

```bash
mkdir -p .local/claude/commits
cat > .local/claude/commits/$(date +%Y%m%d)-commit-<slug>.md << 'EOF'
# <type>: <한글 메시지>

## 포함 파일
- <파일 1>
- <파일 2>
EOF
```

## 주의사항

- `.env`, 시크릿, 비밀번호가 포함된 파일은 절대 커밋하지 않는다.
- 관련 없는 변경사항이 섞여 있으면 분리 커밋을 제안한다.
