# 📄 GitHub Issue 생성 커맨드

## 사용법

```
/issue <작업 내용을 간단히 설명>
```

## 동작 순서

1. `$ARGUMENTS`로 전달된 설명을 바탕으로 작업 내용을 파악한다.
2. 아래 이슈 템플릿을 채워 초안을 작성한다.
3. **사용자 승인을 받기 전에** 초안을 `.local/claude/issues/`에 md로 저장한다. (아래 `## 초안 저장` 참고)
4. 사용자에게 초안을 보여주고 "생성할까요?" 라고 확인을 요청한다.
5. 사용자가 확인하면 즉시 `gh issue create` 명령을 실행하고 생성된 이슈 URL을 출력한다.
6. 수정 요청이 있으면 해당 항목을 수정한 뒤, 수정된 초안을 다시 저장하고 확인을 요청한다.

## 이슈 템플릿

```markdown
## 설명
- 어떤 이슈인지 간단히 작성해주세요.

## 작업 내용
- [ ] 작업 1
- [ ] 작업 2
- [ ] 작업 3

## 참고 자료
- 관련 링크, 문서, 스크린샷 등을 작성해주세요.

## 기타
- 추가로 남길 내용이 있다면 작성해주세요.
```

## 제목 규칙

- `[type] 제목` 형식으로 작성한다.
- `type`은 작업 성격에 맞게 지정한다. 예: `feat`, `fix`, `chore`, `docs`, `refactor`
- 예: `[feat] 콘텐츠 목록 조회 API 추가`

## 각 항목 작성 규칙

### 설명
- "무엇을 왜 하는지" 한 줄로 작성
- 예: `콘텐츠 목록 조회 API 추가 — 타입별 필터와 커서 페이지네이션으로 콘텐츠를 탐색할 수 있도록`

### 작업 내용
- 실제 구현 단위로 체크박스 항목을 3~5개 작성
- 너무 크면 세분화, 너무 작으면 합치기
- 예:
  - `[ ] 콘텐츠 목록 조회 API (GET /api/contents) 구현`
  - `[ ] type(MOVIE/TV_SERIES/SPORT) 필터 및 커서 페이지네이션 지원`
  - `[ ] createdAt / watcherCount / rate 정렬 옵션 추가`

### 참고 자료
- 관련 링크, 문서, 스크린샷 등을 작성
- 없으면 `없음`으로 작성

### 기타
- 논의가 필요하거나 고민되는 부분을 작성
- 없으면 `없음`으로 작성

## 초안 저장

**사용자 승인을 요청하기 전에** 채운 초안을 로컬에 저장한다. (이슈 번호는 아직 없으므로 제목 slug 사용)

- 경로: `.local/claude/issues/<YYYYMMDD>-issue-<slug>.md`
- `slug`: 이슈 제목을 소문자 영문/숫자/하이픈으로 정리한 값 (예: `콘텐츠 목록 조회 API 추가` -> `content-list-api`)
- 내용: 이슈 제목 / 채운 템플릿 본문

```bash
mkdir -p .local/claude/issues
cat > .local/claude/issues/$(date +%Y%m%d)-issue-<slug>.md << 'EOF'
# <이슈 제목>

<채워진 템플릿 내용>
EOF
```

## 이슈 생성 명령

사용자 확인 후 아래 순서로 실행한다.
본문은 특수문자·마크다운 이스케이프 오류를 막기 위해 임시 파일로 작성 후 `--body-file`로 전달한다.

```bash
# 1. 본문을 임시 파일에 저장
cat > /tmp/issue_body.md << 'EOF'
<채워진 템플릿 내용>
EOF

# 2. 이슈 생성
gh issue create \
  --title "<이슈 제목>" \
  --body-file /tmp/issue_body.md

# 3. 임시 파일 삭제
rm /tmp/issue_body.md
```

생성 완료 후 반환된 이슈 URL을 사용자에게 출력한다.
