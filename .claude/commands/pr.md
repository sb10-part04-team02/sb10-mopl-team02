# 📄 GitHub PR 생성 커맨드

## 사용법

```
/pr
```

- 인자 없이 실행하면 현재 브랜치의 변경사항을 분석해 PR 초안을 제안한다.

## 동작 순서

1. `git log`와 `git diff <base-branch>...HEAD`로 현재 브랜치의 전체 변경사항을 파악한다.
2. 브랜치명에서 이슈 번호를 추출한다. (예: `feat/#151/claude-command` → `#151`)
3. 아래 PR 템플릿을 채워 초안을 작성한다.
4. **사용자 승인을 받기 전에** 초안을 `.local/claude/prs/`에 md로 저장한다. (아래 `## 초안 저장` 참고)
5. 사용자에게 초안을 보여주고 "생성할까요?" 라고 확인을 요청한다.
6. 사용자가 확인하면 즉시 `gh pr create` 명령을 실행하고 생성된 PR URL을 출력한다.
7. 수정 요청이 있으면 해당 항목을 수정한 뒤, 수정된 초안을 다시 저장하고 확인을 요청한다.

## PR 템플릿

```markdown
## 🧾 요약
<!-- 이 PR에서 무엇을 변경했는지 간략히 한두 문장으로 설명 -->

## 🔗 이슈
Closes #

## ✨ 작업 내용
<!-- 무엇을 어떻게 작업했는지 구체적으로 -->

-
-

## ✅ 체크리스트
- [ ] 코드 컨벤션을 지켰습니다.
- [ ] 불필요한 코드를 제거했습니다.
- [ ] 주석이 필요한 부분에 추가했습니다.

## 기타
<!-- 기타 내용 -->
```

## 각 항목 작성 규칙

### PR 제목 형식
- `<type>: <한글 제목>` 형식으로 작성한다. (커밋 컨벤션과 동일)
- `feat: ~` — 새로운 기능
- `fix: ~` — 버그 수정
- `refactor: ~` — 리팩토링
- `test: ~` — 테스트 추가/수정
- `docs: ~` — 문서
- `chore: ~` — 설정, 빌드, 기타
- 예:
  - `feat: 리뷰 생성 API 구현`
  - `test: Content CRUD 단위 테스트 구현`
  - `fix: sql 파일 수정`

### 🧾 요약
- 이 PR이 무엇을 왜 하는지 한두 문장으로 작성
- 예: `콘텐츠 목록 조회 API 구현 — 타입별 필터와 커서 페이지네이션으로 콘텐츠를 탐색할 수 있도록`

### 🔗 이슈
- 브랜치명에서 추출한 이슈 번호로 자동 연결
- 예: `Closes #151`
- 이슈 번호를 알 수 없으면 사용자에게 확인

### ✨ 작업 내용
- 실제 변경된 내용을 구체적으로 나열 (커밋 단위가 아닌 기능 단위)
- 예:
  - `콘텐츠 목록 조회 API (GET /api/contents) 구현`
  - `type(MOVIE/TV_SERIES/SPORT) 필터 및 커서 페이지네이션 지원`
  - `createdAt / watcherCount / rate 정렬 옵션 추가`

### ✅ 체크리스트
- 코드 컨벤션 / 불필요한 코드 제거 / 주석 항목은 사용자가 직접 체크하도록 체크박스로 남겨둔다.

### 기타
- 리뷰어가 참고할 내용(스크린샷, 테스트 방법, 논의 필요 사항 등)이 있으면 작성하고, 없으면 비워둔다.

## 초안 저장

**사용자 승인을 요청하기 전에** 채운 초안을 로컬에 저장한다. (PR 번호는 아직 없으므로 브랜치 이슈 번호 사용)

- 경로: `.local/claude/prs/<YYYYMMDD>-pr-<이슈번호>.md`
- `이슈번호`: 브랜치명에서 추출한 번호 (없으면 제목 slug 사용)
- 내용: PR 제목 / 채운 템플릿 본문

```bash
mkdir -p .local/claude/prs
ISSUE_NO="187"   # 브랜치명에서 추출한 번호 (없으면 제목 slug)
cat > ".local/claude/prs/$(date +%Y%m%d)-pr-${ISSUE_NO}.md" << 'EOF'
# <PR 제목>

<채워진 템플릿 내용>
EOF
```

## PR 생성 명령

사용자 확인 후 아래 순서로 실행한다.
본문은 특수문자·마크다운 이스케이프 오류를 막기 위해 임시 파일로 작성 후 `--body-file`로 전달한다.

```bash
# 1. 본문을 임시 파일에 저장
cat > /tmp/pr_body.md << 'EOF'
<채워진 템플릿 내용>
EOF

# 2. PR 생성
gh pr create \
  --title "<타입>: <한글 제목>" \
  --body-file /tmp/pr_body.md \
  --base dev

# 3. 임시 파일 삭제
rm /tmp/pr_body.md
```

생성 완료 후 반환된 PR URL을 사용자에게 출력한다.

## 주의사항

- base 브랜치는 항상 `dev`로 설정한다. `main`으로 보내는 경우 반드시 사용자에게 확인한다.
- 리뷰어 1명 승인 필요 — PR 생성 후 리뷰어 지정을 안내한다.
- 셀프 머지 금지 규칙을 사용자에게 상기시킨다.
